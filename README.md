# 🏫 校园资源预约平台（Campus Resource Reservation Management Platform）

> 一个统一管理校园**实验室、图书馆座位、空教室和体育场馆**的智能预约平台，通过**课表联动、座位图预约、验证码打卡、违规管理和维修管理**，实现校园公共资源的统一预约与动态管理。
>
> 本项目为软件工程课程设计项目。

---

## ✨ 核心特色

本项目不是简单的"四个预约 CRUD 拼在一起"，而是形成了完整的**业务闭环**：

- **统一预约闭环**：资源管理 → 空闲查询 → 预约 → 到场核验 → 使用 → 完成/爽约 → 违规管理
- **课表联动闭环**：课表 → 教室占用 → 空教室计算 → 教室预约
- **维修管理闭环**：用户报修 → 管理员处理 → 暂停资源 → 维修完成 → 恢复使用

核心思想：**预约 ≠ 使用成功，必须完成打卡才能证明实际到场。**

### 四类资源的定位

| 类型 | 预约方式 | 说明 |
| ---- | ---- | ---- |
| 🏫 教室 | **不可预约** | 未被课程占用时可直接使用；系统只展示课表占用（列表红点 + 详情红/绿条形框）✅ |
| 🔬 实验室 | 小组式 · 时段独占 | 每间实验室限 **10 人**，以小组为单位（组长一人预约即可）；按**时段独占**，同一时段冲突才拒绝 ✅ |
| ⚽ 体育馆 | 多人预约 | 允许多人同时预约同一场馆，同一时段数量之和不超过场馆容量 ✅ |
| 📚 图书馆 | 单人座位预约 | 6F/7F 多媒体自习室，每层 60 个座位，采用**可缩放交互式 SVG 座位图**按座位逐一预约 ✅ |

### ⚽ 体育馆多人预约

体育馆不再"一次预约独占整个场馆"，而是**按时段内数量之和**控制容量：

- 预约时填写**使用数量**（单位随场馆而定：游泳馆/篮球场/排球场=人，乒乓球馆=台，羽毛球场/网球场=片）；
- 同一时段内所有有效预约的数量之和不得超过场馆容量，超出会被拒绝并提示剩余数量；
- 场馆列表实时显示**剩余数量**（`容量 - 当前时段已约数量`），标签颜色随占用变化：绿=空闲、黄=部分占用、红=已满；
- 预约详情的时段条为三态：**绿=有空位、黄=部分占用、红=已满**，悬停可看到"已约 X/Y 台"这类明细；
- 体育馆**不适用**"他人已预约则不可进入"的限制：只要未满，其他用户仍可进入查看并预约自己的时段。

> 注：**实验室 / 图书馆座位均按"时段独占"** —— 任何用户都可进入详情页查看时段条、预约其他空档，只有同一时段冲突才会被后端拒绝（`409`）。列表与座位图上的红色标记表示**当前时刻是否有人预约**（红=当前占用），与"今天有没有人约"无关。

### 📚 图书馆座位图（SVG 交互）

图书馆改造为**座位级单人预约**：6F / 7F 各 60 个「多媒体自习位」，每个座位即一条资源记录。

- **楼层切换**：页面顶部在 6F / 7F 之间切换，每层独立渲染 60 个座位；
- **可缩放 / 拖动**：滚轮缩放（60%–300%）、按住拖动平移，右上角提供放大 / 缩小 / 重置控件；
- **座位图形**：每个座位由「桌面 + 显示器 + 座椅」组成，排布为每行 6 座、分 3 组（组内两座相邻），**组内相邻座位之间有竖向隔板**，组间为过道；
- **状态可视化**：空闲=绿、我的预约=蓝（座椅上出现蓝色小人）、他人占用=红（红色小人）、维修中=灰；
- **点击预约**：点击任一非维修座位进入该座位的预约详情页，预约逻辑（时段条、验证码打卡、提前释放 / 暂离）与其他资源完全一致。

## ✅ 预约打卡机制（验证码打卡）

预约开始后，用户需到达预约地点完成打卡，作为"实际到场"的证明。
采用**文字验证码**方式：管理员在管理端查看该资源当日的验证码，到场用户输入验证码即完成打卡。

**打卡时间窗：预约开始前 30 分钟 ~ 开始后 5 分钟。** 预约成功时系统会弹窗提示该时间窗。

```
            预约成功（弹窗提示打卡时间窗）
                    ↓
        开始前 30min ── 开始后 5min
                    ↓
             用户到达预约地点
                    ↓
        向管理员索取当日验证码
                    ↓
              输入 6 位验证码
                    ↓
              校验验证码
                    ↓
                 打卡成功 → 开始使用
                    ↓
        超时未打卡 → 自动释放空间 + 记一次爽约
```

### ✍️ 验证码打卡
每个资源每天生成一个动态验证码（管理端可见并可一键复制）：
```
今日 P101 物理实验室验证码：
       583921
```
用户输入 `583921` 验证成功即完成打卡。

> 验证码每日刷新，不依赖设备定位，任何设备均可稳定使用。

## ⏸ 空间释放与暂离

预约处于"使用中"状态时，用户可对空间做如下操作：

| 操作 | 说明 |
| ---- | ---- |
| 🚪 提前释放 | 主动结束预约，立即释放空间 |
| ⏸ 暂离 30 分钟 | 空间为你保留 30 分钟（任意时间可用）|
| 🍚 暂离 1 小时 | **仅在饭点**可用：午餐 11:00-12:30、晚餐 17:30-19:00；其余时间按钮置灰 |
| ↩️ 结束暂离 | 返回后结束暂离，恢复正常使用 |

- 暂离期间空间**仍保持锁定**（在资源列表中显示为红色小圆点）；
- **暂离超时未返回** → 系统自动释放空间，并记一次违规（扣信用分）。

## 🏫 教室课表（教室不参与预约）

教室**无需预约**：只要没有被课程占用，用户可直接进入使用。系统的作用是**展示课表占用情况**：

- **管理端**「课表管理」支持两种录入方式：**批量导入**（CSV/TXT 或粘贴文本）与**手动填写**（单条表单），并可查询、删除课表记录；
- **用户端**教室列表按"当前是否正在上课"显示红/绿小圆点（红=上课中），点击进入详情查看该教室的**课表安排**；
- 详情页用**红/绿条形框**图形化展示一天的时间段（红=上课占用、绿=空闲可用），点击红色区段可查看该时段正在上的**课程与日程**；
- 调用预约接口预约教室会被拒绝（`教室无需预约，未被课程占用时可直接使用`）。

课表导入格式（每行一条）：

```
教室,课程名称,星期,开始时间,结束时间,教师
A101,高等数学,1,08:00,09:40,张老师
```

> 星期可写 `1~7` 或 `周一~周日`；教师可省略。

> 📄 系统内置的课表来自**武汉理工大学教务系统真实数据**（`src/main/resources/db/campus_courses.csv`）：覆盖 4 个校区、**1262 间已排课教室**，共 **10691 条**课程记录（2026-2027-1 学期），含课程名称、教师、星期与节次，启动时由 `DataInitializer` 自动导入，无需手动操作。
>
> 资源同样来自教务系统采集（`src/main/resources/db/campus_rooms.csv`）：**1463 个**可预约资源 —— 教室 820、实验室 155、体育馆 368、图书馆座位 120，覆盖南湖 / 马房山 / 余家头 / 军山 **4 个校区、53 栋楼**。每个页面的搜索框都单独占一行置顶，下方才是筛选条件：
>
> - **教室**：校区 → 教学楼（多选、可搜索、标签全展开） → 教室类型 → 日期 → 时段
> - **实验室**：校区 → 楼栋 → 实验方向 → 楼层
> - **体育馆**：校区 → 运动场 → 运动类型
>
> 楼栋、楼层、细分类型选项全部来自真实数据，不写死枚举；某个校区没有细分数据时前端自动隐藏该维度。
>
> 细分类型共三类语义：教室取自教务系统 `JASLXDM_DISPLAY`（多媒体教室 408、普通教室 221、学院专用 146、机房 19、制图教室 19、自习教室 5）；实验室按楼栋学科归属（化学 69、化学生物 31、工程实训 22、交通运输 1、管理 1、通用实验 31）；体育馆从场地名解析运动类型（篮球 84、田径 38、网球 37、排球 20、乒乓球 16、羽毛球 13、游泳 12、体能训练 12、足球 11、其余 86 归入综合场地）。

```
             📅 导入课程表
                    ↓
             解析课程信息
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
      课程时间                 教室
        ↓                       ↓
        └───────────┬───────────┘
                    ↓
              建立占用记录
                    ↓
            自动计算空闲教室
                    ↓
             用户查询空教室
                    ↓
               发起预约
```

示例：
```
A101 周一
08:00 ─ 10:00   高等数学      ❌
10:00 ─ 12:00   空闲          ✅
14:00 ─ 16:00   Java程序设计  ❌
16:00 ─ 18:00   空闲          ✅
```

用户直接看到 **"A101 周一 10:00～12:00 可预约"**，而不是自己去查课表。

### 前端实现

资源详情页的预约表单采用 **30 分钟粒度时段网格**：

1. 选择日期后，调用 `getAvailability(resourceId, date)` 获取该日全部时段
2. 每个时段显示三种状态：
   - 🟢 绿色：可预约
   - ⚪ 灰色：已占用（悬浮显示课程名或"已被预约"）
   - 🟣 紫色：已选区间
3. 点击起止时段即可选择连续区间，自动校验：
   - 区间内不能包含已占用时段
   - 总时长不超过资源的 `maxDuration`
4. 占用来源 = 全校课表（按周循环）+ 当日已有预约

数据模型：

```
timetable_entry {
  resourceId, dayOfWeek (1-7),
  startTime, endTime,
  courseName, teacher, semester
}

availability = 开放时段 - 课表占用 - 已有预约
```

### 课表导入入口

管理员登录后，侧边栏「管理后台 → 课表管理」可维护全校课表，提供两种录入方式：

1. **单条新增**：选择资源、星期、起止时间、课程名、教师
2. **批量导入**：粘贴 TSV/CSV 文本，每行一条，格式为：
   ```
   资源ID, 星期(1-7), 开始时间, 结束时间, 课程名, 教师
   ```
   示例：
   ```
   1,1,08:00,09:35,高等数学,王教授
   1,3,14:00,15:35,大学英语,李教授
   ```

课表按周循环（周一至周日），导入后立即影响所有资源的可预约时段计算。

```
                      │

       ↓              ↓              ↓

                      │
              ┌───────┼───────┐
```

### ① 暂停使用
例如实验室101设备故障：`正常使用 → 暂停使用 → 禁止新预约`。

### ② 节假日管理
例如国庆节 10月1日～10月7日：
```
10/01 ───── 10/07
       ↓
   全校资源关闭
```
系统自动阻止这些日期的预约，无需管理员每天手动关闭每个资源。

## 📏 违规规则

设计为**统一模块**，而非每个预约子系统单独实现：

| 行为 | 处理 |
| ---- | ---- |
| 未打卡 | 记一次爽约 |
| 多次爽约 | 限制预约 |
| 超时使用 | 记录违规 |
| 恶意取消 | 扣除信用分 |
| 严重违规 | 暂停预约权限 |

```
                  违规规则
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
      爽约          超时使用       恶意取消
       │             │             │
```

## 🚀 快速开始

### 环境要求

| 依赖 | 版本要求 |
| ---- | ---- |
| JDK | 17 及以上（25 亦可，构建配置已适配） |
| Maven | 3.8+ |
| MySQL | 8.x |
| Node.js | 18+（前端） |

### 1. 初始化数据库

表结构无需手动执行，启动时由 `schema.sql` 自动创建（幂等，可重复执行）；首次启动检测到空库时会自动写入真实数据（管理员账号 `admin` / `admin`，姓名也是 `admin`，**1463 个校区资源**、**10691 条真实课表**、3 条示例预约）。非空库启动时会自动补齐后加的列（如 `room_type`）并同步细分类型。

> ⚠️ 从旧版本（无 `campus` 字段）升级时，需先执行 `src/main/resources/db/rebuild_campus.sql` 清空旧表，再重启后端由 `schema.sql` 按新结构建表。仅新增列（如 `room_type`）的升级不需要清库，启动时会自动补列。

```sql
CREATE DATABASE IF NOT EXISTS campus_reservation DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2. 配置数据库凭据

> ⚙️ **数据库凭据**：`src/main/resources/application.yml` 中的连接用户名/密码通过环境变量注入，默认值为 `root` / `your-mysql-password`（占位符，不含真实密码）。
> 启动后端前请先提供真实密码，例如 PowerShell：`$env:DB_PASSWORD='你的密码'`（也可用 `DB_USERNAME` 覆盖用户名）。
> 在 IDEA 中运行时，可在 Run Configuration → Environment variables 里设置；**请勿将真实密码提交到仓库**。

### 3. 启动后端（端口 8080）

```powershell
$env:DB_PASSWORD='你的MySQL密码'
mvn spring-boot:run
# 或在 IDEA 中直接运行 CampusReservationApplication
```

### 4. 启动前端（端口 5173，Vite 代理 /api → 8080）

```powershell
cd frontend
npm install
npm run dev
```

浏览器访问 http://localhost:5173，使用 `admin / admin` 登录管理端；普通用户在「注册」页填写**姓名、学号、密码**三项即可，登录时用学号 + 密码。学号未注册时会提示「该学号尚未注册」并自动切到注册页、预填学号。

### 5. 运行测试

```powershell
mvn test                    # 77 个单元/集成测试（并发测试需本地 MySQL 运行）
```

### 6. JMeter 并发压测（可选，验收演示用）

```powershell
# 先启动后端，再注册压测账号（一次性），最后执行压测
jmeter -t jmeter\register-users.jmx   # GUI 中运行一次（或命令行 -n 模式）
jmeter -n -t jmeter\reservation-stress.jmx -l jmeter\result.jtl -e -o jmeter\report
# 预期：成功=1、冲突409=19，结论写入 jmeter/stress-result.txt
```
