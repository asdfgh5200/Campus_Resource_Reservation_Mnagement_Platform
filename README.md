# 🏫 校园资源预约平台（Campus Resource Reservation Management Platform）

> 一个统一管理校园**实验室、自习室、空教室和体育场馆**的智能预约平台，通过**课表联动、位置推荐、到场打卡、违规管理和维修管理**，实现校园公共资源的统一预约与动态管理。
>
> 本项目为软件工程课程设计项目。

---

## ✨ 核心特色

本项目不是简单的"四个预约 CRUD 拼在一起"，而是形成了完整的**业务闭环**：

- **统一预约闭环**：资源管理 → 空闲查询 → 预约 → 到场核验 → 使用 → 完成/爽约 → 违规管理
- **课表联动闭环**：课表 → 教室占用 → 空教室计算 → 教室预约
- **维修管理闭环**：用户报修 → 管理员处理 → 暂停资源 → 维修完成 → 恢复使用

核心思想：**预约 ≠ 使用成功，必须完成打卡才能证明实际到场。**

## ✅ 预约打卡机制（双重打卡）

预约开始后，用户需到达预约地点完成打卡，作为"实际到场"的证明。

```
                 预约开始
                    ↓
             用户到达预约地点
                    ↓
              ┌─────┴─────┐
              ↓           ↓
           📍定位打卡     ✍️文字打卡
              ↓           ↓
          判断距离       输入验证码
              ↓           ↓
              └─────┬─────┘
                    ↓
                 打卡成功
                    ↓
                 开始使用
```

### 📍 定位打卡
例如规定距离 ≤ 100 米：
```
实验室101
      ↓
用户当前位置
      ↓
距离 ≤ 100米
      ↓
      ✅
```
若距离过远（如 2.3 km）则**不允许打卡**。

### ✍️ 文字打卡
管理员在资源现场设置一个动态验证码：
```
今日实验室101验证码：
       583921
```
用户输入 `583921` 验证成功即完成打卡。
> 即使定位存在误差，也可以提供另一种验证方式。

## 📍 位置服务

获取用户当前位置后，计算与各资源的距离，并推荐最近地点。

```
             📍 用户当前位置
                    ↓
             获取经纬度
                    ↓
             地图/位置 API
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
   计算资源距离              地点搜索
        ↓                       ↓
   最近的体育馆             附近体育馆
   最近的自习室             附近自习室
   最近的实验室             附近实验室
        ↓                       ↓
        └───────────┬───────────┘
                    ↓
              📍 最近地点推荐
```
例如进入体育馆预约页面：
- 🥇 体育馆A　350m
- 🥈 体育馆B　680m
- 🥉 体育馆C　1.2km

> 可调用高德、百度等地图服务的 Web API。

## 🏫 空教室 + 课表导入

自动计算空闲教室，避免用户自行查课表。

```
             📅 导入课程表
                    ↓
             解析课程信息
                    ↓
        ┌───────────┴───────────┐
        ↓                       ↓
      课程时间                 教室
        ↓                       ↓
        └───────────┬───────────┘
                    ↓
              建立占用记录
                    ↓
            自动计算空闲教室
                    ↓
             用户查询空教室
                    ↓
               发起预约
```

示例：
```
A101 周一
08:00 ─ 10:00   高等数学      ❌
10:00 ─ 12:00   空闲          ✅
14:00 ─ 16:00   Java程序设计  ❌
16:00 ─ 18:00   空闲          ✅
```

用户直接看到 **"A101 周一 10:00～12:00 可预约"**，而不是自己去查课表。

## 👨‍💼 管理员端

管理员围绕一个核心思想管理资源：**"什么时候能预约，什么时候不能预约。"**

```
                 👨‍💼 管理后台
                      │
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
    🏢资源管理      📅预约管理      ⚙️规则管理
       │              │              │
       ├─资源新增     ├─预约审核      ├─预约时长
       ├─资源修改     ├─预约取消      ├─提前预约
       ├─暂停使用     └─预约记录      ├─预约次数
       └─维修状态                    └─打卡规则
                      │
                      ↓
                 🚨 异常管理
                      │
              ┌───────┼───────┐
              ↓       ↓       ↓
            维修     节假日   违规
```

### ① 暂停使用
例如实验室101设备故障：`正常使用 → 暂停使用 → 禁止新预约`。

### ② 节假日管理
例如国庆节 10月1日～10月7日：
```
10/01 ───── 10/07
       ↓
   全校资源关闭
```
系统自动阻止这些日期的预约，无需管理员每天手动关闭每个资源。

### ③ 维修管理（用户 + 管理员双向流程）
```
👨‍🎓 用户发现问题
        ↓
   "申请维修"
        ↓
填写：资源 + 问题描述 + 图片
        ↓
      待处理
        ↓
   👨‍💼 管理员
        ↓
   ┌────┴────┐
   ↓         ↓
确认维修    驳回
   ↓
暂停资源
   ↓
维修中
   ↓
维修完成
   ↓
恢复使用
```

## 📏 违规规则

设计为**统一模块**，而非每个预约子系统单独实现：

| 行为 | 处理 |
| ---- | ---- |
| 未打卡 | 记一次爽约 |
| 多次爽约 | 限制预约 |
| 超时使用 | 记录违规 |
| 恶意取消 | 扣除信用分 |
| 严重违规 | 暂停预约权限 |

```
                  违规规则
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
      爽约          超时使用       恶意取消
       │             │             │
       └─────────────┼─────────────┘
                     ↓
                 记录违规
                     ↓
                 扣除信用分
                     ↓
              ┌──────┴──────┐
              ↓             ↓
           正常用户       违规用户
                            ↓
                       限制预约
```
