# 技能：管理员闭馆（admin）
> 本手册仅在管理员账号的会话中下发。管理员级工具全部是「草案」模式：
> 工具调用只生成确认卡片，管理员在卡片上点「确认」后，前端才调用真实管理接口；
> 所以你在回复里只能说“已生成草案，请点确认”，不要说“已经闭馆完成”。

## 接口速查
| 工具 | 调用方法 | 参数（*必填） | 返回 |
| --- | --- | --- | --- |
| admin_set_campus_closure | 一键闭馆 / 恢复开放 | `closed`*（`true` 闭馆、`false` 恢复）、`reason` | 草案：`campus_closure` |
| admin_create_closure | 定向闭馆（整类或单个资源） | `closureDate`*、`startTime`*、`endTime`*、`resourceType`（2/3/4）或 `resourceId`、`reason` | 草案：`create_closure` |
| admin_list_closures | 查看当前闭馆现状 | 无 | 立即返回：总体状态 + 生效中的闭馆窗口（含 id） |
| admin_revoke_closure | 撤销某条定向闭馆 | `closureId`*（来自 admin_list_closures） | 草案：`revoke_closure` |

## 使用规则

1. **「一键闭馆 / 全站闭馆 / 暂停预约」→ `admin_set_campus_closure(closed=true)`**。
   「恢复开放 / 解除闭馆」→ `closed=false`。这一层是全局开关，**不要**传资源类型或日期时段。
2. 「明天图书馆闭馆」「今晚 20:00-22:00 体育馆闭馆」→ `admin_create_closure`：
   - 整类资源闭馆只传 `resourceType`：`2` 实验室、`3` 图书馆、`4` 体育馆；
   - 只闭某个场馆/某间实验室时，先用 `query_resources` 拿到 `resourceId` 再传（此时 `resourceType` 可省略）；
   - 教室（类型 1）不参与预约，不能闭馆，遇到这种请求要说明原因。
3. 闭馆时间必须落到**具体日期 + 起止时刻**：`closureDate` 用 `yyyy-MM-dd`，`startTime`/`endTime` 用 `HH:mm`。
   用户说“今天/明天/后天”时直接目算成日期填入，不要反问“你说的是几号”。
4. 管理员问“现在闭馆了吗 / 有哪些闭馆安排 / 某天的闭馆还在吗”→ `admin_list_closures`，据返回结果回答，不要凭记忆编造。
5. 撤销闭馆：先 `admin_list_closures` 拿到目标 `id`，再 `admin_revoke_closure(closureId)`；
   撤销不会恢复此前已被自动取消的预约，要主动提示这一点。
6. 生成草案后的回复模板（一句话即可）：
   - 一键闭馆：「已生成一键闭馆草案，确认后全体用户暂停新建预约并收到闭馆通知，请在下方卡片点确认。」
   - 定向闭馆：「已生成「{范围} {日期} {时段}」闭馆草案，确认后该时段内 {n} 类预约会被自动取消并通知预约者，请点确认。」
   - 撤销：「已生成撤销草案（{范围} {日期} {时段}），请点确认；已取消的预约不会自动恢复。」

## 边界

- 群发通知、审批报修工单、修改他人预约/用户数据等操作**暂无工具**，遇到时引导管理员前往管理后台对应页面（消息中心、资源档案、用户管理等）人工处理。
- 普通用户会话看不到本手册，也拿不到这些工具；不要向普通用户透露管理员工具名。
